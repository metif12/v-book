# AGENTS.md

## Project

A book for the V programming language, published as a static site generated by
V itself. Target runtime: V 0.5.2+, with the CI workflows building V from source
because the generator uses the current `$tmpl('file.html', data)` API and veb's
static compression. Canonical source is Markdown in `src/`, code examples in
`listings/`. No mdBook, no Rust toolchain, no Node — the site builder is V plus
`veb`.

## Commands

```bash
v run site                        # Build the whole site into dist/ (all locales)
v run site dist-preview           # Build into another directory
v run site serve                  # Build, then preview at http://localhost:8090/v-book/
v run tools/code_check.vsh         # Compile + run every `v` code block (src + all translations)
v run tools/code_check.vsh src     # Same, English source only — what CI runs
v run tools/validate.vsh          # Lint book structure (CI references this)
v test .                          # Run V unit tests
```

## Code example conventions

- `v` — compiled and run in CI (must pass)
- `v ignore` — not compiled (pseudocode, incomplete)
- `v no_run` — compiled but not run (blocking examples, templates that need files)

The tester (`tools/code_check.vsh`) extracts fenced code blocks and writes each
`v` / `v no_run` block to its own temp `main.v`, then runs it with `v run` (or
`v -check` for `no_run`). A failing block fails CI. Blocks with no language, or
`bash`/`sh`/`console`, are skipped.

## Structure

- `src/` — English Markdown (canonical source)
- `listings/` — V code examples organized by chapter
- `translations/<code>/` — 16 language dirs; `src/` mirrors the English tree
- `site/` — the site builder:
  - `main.v` — build, preview (`serve`), sitemap, robots, 404, root index
  - `markdown.v` — Markdown renderer (headings, paragraphs, code, lists,
    tables, blockquotes, inline marks)
  - `site.v` — page data, navigation, locales, language menu, search index
  - `search.v` — full text search documents, one per section
- `site/templates/` — the shell, compiled in by `$tmpl`:
  - `page.html` — the whole page shell
  - `landing.html` — the redirect card at the site root
- `static/` — assets copied verbatim into `dist/`:
  - `app.css` (chrome: top bar, search panel, TOC, theme, code shell)
  - `book.css` (prose typography)
  - `app.js` (theme, Ctrl+K search, panels, code highlighting, offline)
  - `logo.svg`, `favicon.png`, `icon-192.png`, `icon-512.png`, `og-image.png`
  - `manifest.webmanifest`, `sw.js` (the offline shell)
  - `codemirror/`
- `tools/code_check.vsh`, `tools/validate.vsh` — CI gates
- `tools/make_icons.vsh` — draws the PWA icons and the social card as PNGs
- `.github/workflows/` — `main.yml` (tests, build, validate) and `pages.yml`
  (deploy `dist/` to GitHub Pages)

## Publishing

The canonical site is `https://metif12.github.io/v-book/`, served under the
`base_path = '/v-book/'` constant in `site/site.v`. Every absolute URL in the
shell, the search index and the sitemap is built from that constant, so the
local preview (`v run site serve`) mounts it identically.

## Gotchas

- V code blocks must be self-contained (each block is written to a temp
  `main.v` and run independently).
- String interpolation in V uses `${...}` inside single-quoted strings.
- The `v` code block language must be exactly `v`, `v ignore`, or `v no_run`.
- `site/site.v` holds static strings with double quotes inside single-quoted V
  strings; keep that quoting when editing HTML there.
- A translation's `SUMMARY.md` drives that locale's pages, so a page absent
  from it is simply absent from that language's build.
- The `ar`, `fa` and `ur` locales are right-to-left; the shell sets `dir`, and
  `book.css` has the RTL rules.
- Editing `site/` requires `v fmt -w site` to stay clean; run `v -check site`
  after every change.
